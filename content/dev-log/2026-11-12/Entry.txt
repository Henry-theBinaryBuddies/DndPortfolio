Artifact 5 (Tome & Tile):

The moonshot stopped being a dungeon map maker today. The map maker had already become the Scenic Sorcerer side quest, so I made the moonshot what I had really been circling: an open-source virtual tabletop that competes with Roll20 and Foundry. It is called Tome & Tile and lives in a repository of its own, with John and Adrian on the team and a Claude for each of us. Before any code I asked Claude to interview me at length. I told it to ask more questions than felt necessary and to keep the boundaries strict and the coupling loose, so that a task handed to someone else's Claude could not break mine.

The interview became the skeleton. A Rust server owns all game state and every dice roll. The map is drawn by a renderer written in Rust and compiled to WebAssembly, with TypeScript for everything around it, and every message between the parts is defined once, in Protocol Buffers, with the Rust and TypeScript code generated from it. I decided there are no automated death saves, and that a player's roll is always public, with only the GM able to hide one. Claude wrote thirteen short decision records, a rule file for each of our Claudes saying which folders it may touch, a script that fails the build if one area imports from another, issue templates, CI, and setup guides for Windows.

The video call was the decision I pushed on. Claude first leaned towards peer-to-peer calls. I said TURN had not worked well for us in CouchCrew, and Claude withdrew its own proposal. We chose a media server, LiveKit, because every browser then needs only one outbound connection. Claude also found that a Cloudflare Tunnel cannot carry the media itself, which is why the class version uses LiveKit's hosted service.

Installing Rust took a while. The installs had worked, but the terminal had a stale path and PowerShell would not run npm's script files, and together they looked like a wall of "not recognized" errors. Both fixes are now in the setup guide for John and Adrian. By the afternoon the repository was on GitHub with main protected and CI required, and there was a mock server that speaks the real protocol, so the others can build screens before the real server exists. By the evening there were five ready-made level 3 characters from the free SRD rules. Claude caught two mistakes in them on review: the cleric had no way to wear heavy armour, and the rogue's Cunning Action was marked passive when it is a bonus action. Claude wrote the character numbers from memory, and they have not been checked against the SRD itself, so that is still to do.
