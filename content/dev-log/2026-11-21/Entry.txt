Artifact 5 (Tome & Tile):

This was the week the first milestone was due, and it is done except for one piece. A GM can now upload a map picture and every player sees it. Tokens move in sync across browsers, and the chat and dice panels work. Before writing the upload I had to decide where it should run, because the code that checks pictures belongs to Adrian's part of the project and the server is not normally allowed to use it. Claude wrote that decision up as a short design record, I accepted it, and the server now uses that one library and nothing else of Adrian's. The missing piece is the video call. It needs a LiveKit account that I have not finished setting up, so the call has never run for real, only against a fake.

Then I moved on to the second milestone, which is about combat. Claude filed thirteen issues for the three of us, and I finished all of mine: the five pregenerated characters standing on a map, the rules for an attack roll against armour class and damage on a hit, warnings when a target is out of range or there are too many targets, both servers answering an attack, and a way to click tokens on the map to choose targets. Nobody loses hit points yet; that comes next week. Claude had Sonnet helpers write most of the routine code while it reviewed, and for the larger pieces a group of reviewer agents went through each change with a skeptic double-checking every complaint. That caught real things. A monster's remaining uses of an ability would have leaked to the players through a warning message. Five tests would have passed even if the code were broken. And tapping a token on a phone would often fail, because a finger wobbles more than the three pixels a mouse click is allowed.

Twice I had to step in. Once a test opened a network port to the whole machine, and Windows asked me whether to let it through the firewall. I asked Claude what the program was, and every test now stays on the local machine only. Another time a safety check refused a merge because all I had said was "continue in order", and Claude waited for me to say yes plainly instead of finding a way around it. I also reviewed everything John and Adrian sent. John's map and upload control, and Adrian's picture checker and call module, are merged; their combat and video pieces are open with small fixes requested. I wrote the weekly check-in report for Sunday.

Side Quest (Adventurer Anvil):

Characters now save themselves in the browser half a second after each change, and can be downloaded and opened again as files. Every file is checked before it opens, so one from a newer version of the app, another game or a damaged download is refused with the reason. If the same character is open in two tabs and one of them saves, the other stops saving until I choose which copy to keep. A test at phone size found that the save status and the Characters button were hidden there.

Then levels 1 to 20 and multiclassing. The SRD pack already had every class's levels, so the work was in the rules: the first class keeps the levels the others don't take, only it gives saving throws, each class's score prerequisites are checked (a DM can allow one that isn't met), hit points take the average after 1st level, and two spellcasting classes share the multiclass slot table while a warlock's Pact Magic stays separate. Ability Score Improvements, Eldritch Invocations with their prerequisites, Mystic Arcanum and Magical Secrets all became choices. Claude's design note had one slot count wrong for a Paladin 3 / Sorcerer 3; the table the code uses has it right, and a test checks it. A Level up button now sits on Review and on each saved character.

Next came the optional rules, on a new Rules step: a feat instead of an Ability Score Improvement (the SRD has only one, Grappler, entered from its text), rolled hit points with every roll kept and rerolls noted, variant encumbrance, and moving a race's ability increases to other scores. Variant Human isn't in the SRD, so a pack can mark a race as needing the feats rule, ready for my own.

Last, the character sheet, on screen and for printing: two pages with the ability scores, saves and skills marked for proficiency, the combat numbers, features with the level they come from, spells by level and the character's story, then any DM rulings and the SRD credit. It prints black on white without the app around it. Its tests caught two things on the way: the features list had no text for the full-text print option, and some comments in the core used game words, which a test forbids so that the core stays game-agnostic.

I merged all of it to master. 263 unit tests and 43 browser tests pass, with accessibility checked at desktop and phone sizes. Three smaller pieces of the first milestone are left: an inventory editor, a session journal and a written guide to the pack format.
A big day for the character builder, in four steps, each done by Claude and merged by me as one pull request.

Saving. A character now saves itself in the browser half a second after each change, and can be downloaded as a file and opened again. A file is checked before it opens: files that are not characters, come from a newer version or are damaged are refused with a reason, and older ones are upgraded. If the same character is open in two tabs, saving pauses until I choose which copy to keep.

Levels one to twenty. A character can now be any level, take levels in other classes, and level up from Review or the list. That meant teaching the content format about ability score improvements, other classes' prerequisites and each class's spell progression, and re-reading the SRD for every class's invocations and secrets. Hit points, spell slots for mixed casters and the multiclass rules all follow from it.

Optional rules. Each character picks its own: multiclassing, feats, rolled hit points, variant encumbrance and a custom origin. Turning a rule off deletes nothing; its choices just stop counting, and Review lists them.

The character sheet. A sheet on screen that prints: abilities, saves, skills with proficiency marks, attacks, features with the level they came at, spells grouped by level with the prepared ones marked, and the story on the second page. Printing leaves out the app's frame and gives one sheet per page. It adds the DM's rulings and the credits for the content to every sheet.
